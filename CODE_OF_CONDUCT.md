# Code of conduct

We want technical disagreement to be direct, evidence-based, and safe for contributors.

## Expected behavior

- Treat people with respect regardless of identity, background, experience, or viewpoint.
- Critique designs and evidence, not people.
- State uncertainty and correct errors openly.
- Protect security reports, personal information, credentials, and test data.
- Accept maintainer decisions about scope, disclosure timing, and the Phase 0 boundary.

## Unacceptable behavior

- Harassment, threats, discrimination, sexualized conduct, stalking, or doxxing.
- Publishing a vulnerability before coordinated disclosure.
- Pressuring contributors to reveal identity, private contact information, or sensitive evidence.
- Knowingly overstating security, audit, anonymity, deletion, or readiness claims.
- Disrupting project infrastructure or another person's systems or data.

## Enforcement

Maintainers may edit or remove contributions and communications, warn participants, temporarily limit
participation, or permanently ban serious or repeated violations. Reports about conduct should use a
private repository security advisory (Security → Report a vulnerability) with `Conduct report` in the
title. The same maintainers receive that private channel; do not place sensitive conduct reports in a
public issue. A dedicated private conduct contact should replace this temporary route if the community
grows.
